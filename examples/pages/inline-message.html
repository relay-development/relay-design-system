インラインメッセージ

component

操作の結果を、操作した場所のすぐ近く（ボタンの横・フォームの直下・テーブルの行内）で短く伝えるメッセージです。アイコンと 1 行の文言だけで枠を持たず、時間で消えるトーストやスナックバーの代わりに「その場に残す」ための部品です。

success / negative / warning / neutral。文字とアイコンが同色で、背景・枠は持たない

フィードバックの行き先

操作へのフィードバックは「どこに置くか」と「消え方」で 4 つに分ける。時間で勝手に消える通知（トースト / スナックバー）は用意しない

状況 使うもの 例
結果が画面を見れば分かる単純な成功 出さない チェックを入れた・行が 1 件増えた・並び順が変わった
操作した場所の直近で結果を短く伝える inline-message 「保存する」の横に「保存しました」、送信ボタンの下に「送信に失敗しました」
ページ全体に向けた常設のお知らせ・しばらく残す通知 alert メンテナンス予定、審査結果の通知、ページ上部のエラー要約

置き場所と消え方
Good

保存しました

押したボタンの横に出し、次の操作まで残す。視線を動かさずに結果が分かり、拡大表示や読み上げでも見逃さない。

<button class="btn …">保存する</button>
<p class="[[inline-message inline-message-success]]" role="status">…保存しました</p>
Don't
保存しました 3 秒後に消える

画面の隅に固定して数秒で消すトースト。操作した場所から離れていて、拡大表示では視野に入らず、読み終える前に消える。

<div class="[[fixed bottom-4 right-4]] …">保存しました</div>
[[setTimeout]](() => toast.remove(), 3000)

結果が見て分かる操作には出さない

出す / 出さないの判断
Good

スイッチが ON に変わったこと自体が結果。メッセージを足すと画面が騒がしくなるだけで情報は増えない。

Don't

設定を更新しました

切り替えるたびに「更新しました」を添える。すべての操作に添えると、本当に伝えるべき失敗が埋もれる。

インラインメッセージのアクセシビリティ

トーストを避ける理由の大半がここにあります。時間で消さない（WCAG 2.2.1）、操作した要素の直後に置く（WCAG 1.3.2）、動的に出すなら role="status"／role="alert"（WCAG 4.1.3）の 3 点を守れば、拡大表示・読み上げ・時間がかかる利用者にも同じ情報が届きます。置き場所の決め方とトーストを用意しない理由は システムフィードバックのアクセシビリティ、WCAG 2.2 全基準は アクセシビリティ ページを参照。

期待される配慮

Presentation / Adaptability / Interaction / Assistive Technology

提示

意味は色だけでなくアイコン＋文言で伝える。各テーマの文字色は白背景で本文コントラストを確保。

適応

操作した要素の直近に置くため、拡大表示（ズーム・スクリーン拡大鏡）でも操作対象と一緒に視野へ入る。長文は折り返す。

操作

時間で消えない。読むのに時間がかかる利用者も、次の操作を自分のペースで選べる。

支援技術

動的表示は role="status"（成功・neutral）／role="alert"（失敗・注意）でフォーカスを奪わずに読み上げ、DOM 上の位置も操作した要素の直後にする。

DS が担保する機能

追加実装なしで満たされる

  • ✓各テーマの文字色は白背景でコントラスト比 4.5:1 以上
  • ✓アイコンスロットが行高と揃い、拡大しても 1 行目とずれない
  • ✓背景・枠を持たないため、強制カラーモードでも追加対応なしで文字とアイコンが見える

実装時の必須対応

プロダクト側で担保する

  • !動的に挿入する結果に role="status"（success・neutral）／role="alert"（negative・warning）を付ける
  • !DOM 上も操作した要素の直後に挿入する（読み上げ順と視覚上の位置を一致させる）
  • !時間で自動消去しない。消えるのは利用者の次の操作か明示的な操作のみ
  • !アイコンは aria-hidden="true"。テーマと文言を一致させる

テスト方法

スクリーンリーダー / 拡大表示 / 自動チェック

  • SR操作した瞬間、フォーカスを移さずにメッセージが読み上げられる。矢印キーで次に読むのがそのメッセージになっている
  • 拡大400% ズームやスクリーン拡大鏡で操作した要素を見ている状態のまま、メッセージが視野に入る
  • 時間1 分放置してもメッセージが残っている
  • 自動axe / Lighthouse で role・コントラスト・aria-hidden を確認

DOM 上も操作した要素の直後に、role を付けて挿入する

保存できませんでした

ボタンの直後に role="alert" 付きで挿入。フォーカスはボタンに残り、読み上げ順も「ボタン → 結果」になる。

<button class="btn …">保存する</button>
<p class="inline-message inline-message-negative" [[role="alert"]]>…</p>

保存できませんでした

role が無い、または body 末尾のコンテナに挿入する。見た目は同じでも、読み上げでは気づかれないか、どの操作の結果か分からない。

<p class="inline-message inline-message-negative">…</p>  <!-- [[role なし]] -->
document.body.append(msg)  <!-- [[操作した要素から離れた場所]] -->
