# Relay Design System × WCAG 2.1 Level AAA 実務チェックリスト

このドキュメントは **WCAG 2.1 の Level AAA** に準拠したいプロダクトが、Relay Design System を採用した時に「どこまで DS が担保していて、どこから自分たちで実装する必要があるか」を 1 枚で把握するためのチェックリストです。

> - [WAIC 翻訳 - WCAG 2.1 達成基準](https://waic.jp/translations/WCAG21/)
> - [W3C - WCAG 2.1 (Recommendation)](https://www.w3.org/TR/WCAG21/)
> - [WAIC - JIS X 8341-3:2016 準拠表記ガイドライン](https://waic.jp/docs/jis2016/compliance-guidelines/202104/)

## 0. このドキュメントの読み方

### 対象読者

- Relay Design System を採用し、サイト全体で **AAA 準拠** を主張したいプロダクトチーム
- アクセシビリティ監査 / レビューで使うチェック項目を探している人

### 凡例

各達成基準には以下のマーカーを付けてあります。

| マーカー | 意味 | プロダクト側のアクション |
|---|---|---|
| ✅ | **DS で完全担保** | DS のクラス・トークンを使えば自動で満たす |
| ⚠️ | **DS + プロダクト共同** | DS が下地を提供。プロダクトが正しく使う |
| 🔧 | **プロダクト側で実装** | DS は関与しない。プロダクト固有の責務 |
| ⏩ | **コンテンツ次第で適用外** | 動画 / 音声 / セッション等が無ければ対象外 |

## 1. AAA 準拠の前提

### Level の階層

```
Level A   (最低限)    →  Level AA  (標準・法規制の主要ライン)  →  Level AAA (最高)
   ↑                        ↑                                    ↑
   30 基準                   20 基準                              28 基準
```

**Level AAA を主張するには、A と AA をすべて満たした上で AAA も満たす必要があります。** 本書は AAA 専用ですが、A/AA が未対応であれば先にそちらを完了してください。

### Relay Design System の全体的な担保サマリ

| 項目 | DS の実装状況 |
|---|---|
| コントラスト (本文) | `fg-high` (≈18:1) / `fg-middle` (≈10.7:1) → **7:1 超え** ✅ |
| コントラスト (補助) | `fg-low` (≈4.5:1) → **AA 止まり。本文には使わない** ⚠️ |
| キーボード操作 | 全 interactive コンポーネントに `focus-visible` 実装 ✅ |
| Focus ring | `--shadow-focus-ring` トークンで統一 ✅ |
| ARIA 状態 | `aria-pressed` / `aria-selected` / `disabled` ベース ✅ |
| ターゲット最小 44px | `.btn-lg` / `.icon-btn-lg` / `.input-lg` のみ ⚠️ |
| `prefers-reduced-motion` | **未対応** 🔧 |
| 見出し階層 | `.typo-*` (xsmall→3xlarge) で提供 ⚠️（プロダクトが選択） |

## 2. Perceivable (知覚可能) — 9 基準

### 1.2.6 手話 (収録済) ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディアの音声に対し、手話通訳を提供する。

- 動画コンテンツを持たない場合は **適用外**
- 動画を持つ場合は **🔧 プロダクト側で実装**（手話ワイプ動画の埋め込み等）

**チェック**:
- [ ] サイト内に収録済み同期メディアは存在するか
- [ ] 存在する場合、各動画に手話通訳トラックが付いているか

---

### 1.2.7 拡張音声解説 (収録済) ⏩ コンテンツ次第

**達成基準**: 収録済み動画に対し、台詞の合間に収まらない映像情報を補う「拡張音声解説」を提供する。

- 動画コンテンツを持たない場合は **適用外**
- 動画を持つ場合は **🔧 プロダクト側で実装**

**チェック**:
- [ ] 動画の映像情報が音声だけで理解できるか
- [ ] 不足する場合、拡張音声解説トラックを別途用意できているか

---

### 1.2.8 メディアに対する代替 (収録済) ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディアと、収録済み映像のみのメディアに対し、時間依存メディアの代替（テキスト書き起こし等）を提供する。

- 動画 / 音声を持たない場合は **適用外**
- 持つ場合は **🔧 プロダクト側で実装**（全文トランスクリプトの提供）

**チェック**:
- [ ] 全ての収録済み動画・音声にトランスクリプトが用意されているか
- [ ] トランスクリプトに視覚情報の記述も含まれているか

---

### 1.2.9 音声のみ (ライブ) ⏩ コンテンツ次第

**達成基準**: ライブ音声のみコンテンツに対し、同等の代替（リアルタイム文字起こし等）を提供する。

- ライブ配信を持たない場合は **適用外**

**チェック**:
- [ ] ライブ音声配信があれば、同時字幕 / リアルタイムキャプションを提供しているか

---

### 1.3.6 目的の特定 ⚠️ DS + プロダクト共同

**達成基準**: 各 UI コンポーネントの目的を、プログラム的に判別可能にする（autocomplete 属性、ARIA Landmark など）。

**DS 側の担保**:
- ボタン / 入力欄 / セレクト等は意味のある HTML 要素を使用
- 状態は ARIA 属性 (`aria-pressed`, `aria-selected`, `disabled` 等)

**プロダクト側の責務**:
- `<input>` には用途に応じた `autocomplete` 属性を付与（`name`, `email`, `tel`, `street-address` 等）
- ページのランドマーク (`<header>`, `<nav>`, `<main>`, `<footer>`) を適切に配置
- アイコンのみのボタンには `aria-label` を必ず付与

**チェック**:
- [ ] フォーム入力欄に適切な `autocomplete` 属性があるか
- [ ] アイコンボタン (`.icon-btn`) すべてに `aria-label` があるか
- [ ] ページ構造にランドマーク要素が使われているか

---

### 1.4.6 コントラスト (高度) ✅ DS で担保

**達成基準**: テキスト・文字画像のコントラスト比 **7:1 以上**（大きい文字は 4.5:1 以上）。

**DS 側の担保**:
- `--color-fg-high` (slate-900) on white = **約 18:1**
- `--color-fg-middle` (slate-700) on white = **約 10.7:1**
- `--color-fg-low` (slate-500) on white = **約 4.5:1** → **AA 止まり、AAA 本文には使わない**

**プロダクト側の責務**:
- 本文には `text-fg-high` または `text-fg-middle` を使う
- 補助テキストに `text-fg-low` を使う場合、それは **AA 規格** であることを認識する（AAA では補助情報も 4.5:1 以上のため大きいフォントでのみ可）
- カスタム配色を作る場合、必ず WebAIM 等のコントラストチェッカーで 7:1 を確認

**チェック**:
- [ ] 本文に `text-fg-high` / `text-fg-middle` を使用しているか
- [ ] カスタム配色のコントラスト比を測定したか（≥ 7:1）
- [ ] 大きい文字 (18pt 以上 or 14pt+bold) は 4.5:1 でも可

**検証ツール**: Chrome DevTools / axe DevTools / WebAIM Contrast Checker

---

### 1.4.7 小さな背景音、又は背景音なし ⏩ コンテンツ次第

**達成基準**: 収録済み音声に背景音がある場合、前景音より **20dB 以上小さい** か、無いこと。

- 音声コンテンツを持たない場合は **適用外**

**チェック**:
- [ ] 音声コンテンツの BGM / 環境音が前景音より十分小さいか

---

### 1.4.8 視覚的提示 ⚠️ DS + プロダクト共同

**達成基準**: テキストブロックに対し以下を提供:
- 前景色 / 背景色を利用者が選択可能
- 1 行 80 文字以下（CJK は 40 文字以下）
- 両端揃えにしない
- 行間 1.5 倍以上、段落間隔は行間の 1.5 倍以上
- 200% まで拡大できる

**DS 側の担保**:
- `.typo-*` クラスは line-height を `var(--text-xs--line-height)` 等で 1.5 前後に設定
- 余白は spacing トークンで段落間隔を作りやすい

**プロダクト側の責務**:
- 本文の最大幅を 40〜80 文字相当 (`max-width: 65ch` 等) で制限
- `text-align: justify` を使わない
- ユーザーが背景色を変更できる仕組み (テーマ切替 / カスタム CSS 適用) — AAA では必要

**チェック**:
- [ ] 本文の段落幅が読みやすい範囲か
- [ ] 両端揃え (`justify`) を使っていないか
- [ ] 200% ズームで横スクロール無しに読めるか
- [ ] テーマ切替などで配色を変えられるか

---

### 1.4.9 文字画像 (例外なし) 🔧 プロダクト側

**達成基準**: テキストを画像に焼き付けない。**例外なし**（ロゴ・装飾文字は除く）。

**DS 側**: 文字画像は使っていません。

**プロダクト側の責務**:
- 見出し・本文・ボタンラベル等は **すべて HTML テキスト** で記述
- 「ヒーロー画像にキャプションを焼き込む」「メニュー画像内に文字」等を避ける
- 例外はロゴ・ブランドマークのみ

**チェック**:
- [ ] テキストが画像として配信されている箇所が無いか
- [ ] 装飾用テキスト画像にも `alt` が付いているか

## 3. Operable (操作可能) — 12 基準

### 2.1.3 キーボード (例外なし) ✅ DS で担保

**達成基準**: すべての機能をキーボードのみで操作可能。**タイミング依存もダメ**。

**DS 側の担保**:
- 全 interactive コンポーネント (`button`, `a`, `input`, `select`, `textarea`, `[role=tab]` 等) はネイティブにキーボード対応
- `:focus-visible` で focus ring を提供（`--shadow-focus-ring` または `outline-info-600`）
- マウスホバー専用の hidden UI は無い

**プロダクト側の責務**:
- `tabindex="-1"` の濫用や、`<div onclick>` 等の非標準クリック要素を避ける
- カスタム widget を作る場合は WAI-ARIA Authoring Practices に従う
- ショートカット (`accesskey` 等) は無効化可能にする

**チェック**:
- [ ] Tab 順序で全ての interactive 要素にフォーカスが当たる
- [ ] Tab で進めない・抜け出せない箇所（フォーカストラップ）が無い
- [ ] Enter / Space / Esc / 矢印キーなど期待される操作がすべて動く
- [ ] フォーカスが視覚的に常に分かる

---

### 2.2.3 タイミング非依存 🔧 プロダクト側

**達成基準**: コンテンツや機能の利用にタイミングが必須でない（リアルタイムイベント・必須のオークション等を除く）。

**プロダクト側の責務**:
- フォーム送信、CAPTCHA、課題回答などに制限時間を設けない
- どうしても必要な場合は十分な代替手段を提供

**チェック**:
- [ ] フォーム入力・課題等にタイマー制限が無いか
- [ ] あれば、リアルタイムイベント等の必須要件を満たすケースのみか

---

### 2.2.4 割り込み 🔧 プロダクト側

**達成基準**: 緊急時を除く割り込み（通知 / モーダル等）は、利用者が **延期・抑止できる**。

**プロダクト側の責務**:
- 通知バナー / モーダル / 自動更新等を **ユーザー設定で無効化可能** にする
- ライブ通知 (Toast) のタイムアウトをユーザーが延長できる

**チェック**:
- [ ] 通知をユーザーがオフにできるか
- [ ] モーダル / ポップアップは Escape で閉じられるか
- [ ] 自動更新コンテンツを一時停止できるか

---

### 2.2.5 再認証 🔧 プロダクト側

**達成基準**: 認証セッションが切れて再認証した時、**入力中のデータが失われない**。

**プロダクト側の責務**:
- フォームの入力中データを localStorage 等にバックアップ
- セッション復帰後に入力状態を復元

**チェック**:
- [ ] セッション切れ → 再ログイン → 元のフォーム画面に入力内容が戻るか
- [ ] 長文入力中に勝手にセッションが切れない (もしくは延長警告がある)

---

### 2.2.6 タイムアウト 🔧 プロダクト側

**達成基準**: 操作の不実行で **データ損失が起きるタイムアウト** がある場合、20 時間以上の利用者非活動が前提か、20 秒以上前に警告する。

**プロダクト側の責務**:
- セッションタイムアウト前に **20 秒以上前のモーダル警告** を表示
- 警告で「延長」「再認証」「データ保存」の選択肢を提供

**チェック**:
- [ ] セッション切れ前に警告ダイアログが出るか
- [ ] 警告は 20 秒以上前に表示されるか
- [ ] 「延長」操作で復帰できるか

---

### 2.3.2 3 回の閃光 ✅ DS で担保

**達成基準**: 1 秒あたり 3 回以上の閃光をどのコンテンツにも含めない。

**DS 側の担保**:
- アニメーションは `transition-colors duration-150` 等の穏やかな色変化のみ
- スピナー (`.btn[data-loading]`) は連続回転で閃光ではない
- 閃光・点滅アニメーションは存在しない

**プロダクト側の責務**:
- 自作の演出（GIF, 動画, Lottie 等）に閃光を含めない

**チェック**:
- [ ] 1 秒に 3 回以上の明暗変化を持つ要素が無いか
- [ ] 自作アニメーションが flash trigger になっていないか

---

### 2.3.3 インタラクションによるアニメーション ⚠️ DS は要強化

**達成基準**: 操作で起きる必須でないモーションアニメーションを無効化できる。

**DS 側の現状**:
- ✅ 多くのコンポーネントが `transition-colors duration-150` (色変化のみ。モーションではない)
- ⚠️ ボタンのローディングスピナー (`btn-spin 0.6s linear infinite`) は **`prefers-reduced-motion` 非対応**
- ⚠️ `transition-opacity` 等を使うアラート開閉も同様

**プロダクト側の責務**:
- `@media (prefers-reduced-motion: reduce)` でアニメーションを止めるグローバル CSS を **プロダクト側で追加**
- 例:
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```

**チェック**:
- [ ] OS の「視差効果を減らす」設定でアニメーションが停止 / 短縮されるか
- [ ] パララックス・スクロール演出を無効化できるか

**今後の DS 改善案**: DS 側でも `@media (prefers-reduced-motion: reduce)` を baseline に追加することを検討。

---

### 2.4.8 現在位置 🔧 プロダクト側

**達成基準**: 一連のページ内で、利用者が現在位置を把握できる情報を提供。

**プロダクト側の責務**:
- パンくずリスト (`<nav aria-label="breadcrumb">`)
- 現在ページのナビゲーション項目に `aria-current="page"`
- ページタイトル (`<title>`) の明確化

**チェック**:
- [ ] パンくずまたはサイトマップが提供されているか
- [ ] 現在ページのナビ項目が視覚的・プログラム的に区別されているか

---

### 2.4.9 リンクの目的 (リンクのみ) ⚠️ DS + プロダクト共同

**達成基準**: リンクテキストだけで目的が分かる（周辺コンテキストを読まなくて良い）。

**DS 側の担保**:
- `.btn` / `.icon-btn` の構造はラベルテキストを直接書き込む設計

**プロダクト側の責務**:
- 「こちら」「more」「Read more」のような曖昧なリンク文言を避ける
- 「資料 PDF をダウンロード」のように行き先を文言に含める
- アイコンのみのリンクに `aria-label` 付与

**チェック**:
- [ ] リンク文言を抜き出して読んでも目的が分かるか
- [ ] 同じ文言で別の場所に飛ぶリンクが無いか

---

### 2.4.10 セクション見出し ⚠️ DS + プロダクト共同

**達成基準**: コンテンツが階層化されている場合、各セクションに見出しを付ける。

**DS 側の担保**:
- `.typo-3xlarge` / `.typo-2xlarge` / `.typo-xlarge` / `.typo-large` / `.typo-medium` 等の階層
- 各セクション見出しに対応するスタイルを提供

**プロダクト側の責務**:
- 適切な `<h1>`〜`<h6>` の階層構造を組む（`<h1>` の下に `<h3>` を直接置かない）
- 装飾だけのために見出しを使わない（typo-* を div / span に当てれば良い）

**チェック**:
- [ ] 見出し階層が論理的に正しい（h1 → h2 → h3 …）
- [ ] スクリーンリーダーの見出しジャンプで内容を把握できる

---

### 2.5.5 ターゲットのサイズ ⚠️ DS + プロダクト共同

**達成基準**: ポインタ入力のターゲットサイズは **44 × 44 CSS px 以上**。

**DS 側の実情**:

| コンポーネント | サイズ | AAA 適合 |
|---|---|---|
| `.btn-sm` | h-8 = 32px | ❌ |
| `.btn-md` | h-10 = 40px | ❌ |
| `.btn-lg` | h-12 = 48px | ✅ |
| `.btn-xl` | h-18 = 72px | ✅ |
| `.icon-btn-sm` | 32×32 | ❌ |
| `.icon-btn-md` | 40×40 | ❌ |
| `.icon-btn-lg` | 48×48 | ✅ |
| `.input-sm` | h-8 = 32px | ❌ |
| `.input-md` | h-10 = 40px | ❌ |
| `.input-lg` | h-12 = 48px | ✅ |

→ **AAA を目指す画面では `lg` サイズを基本に使う**。

**例外（AAA でも許容される）**:
- インライン (テキスト中のリンク等)
- ユーザーが拡大できる場合
- 同等の代替手段がある場合

**チェック**:
- [ ] 重要な操作対象に `lg` サイズを使用しているか
- [ ] sm / md を使う場合、十分な余白で間隔をとっているか

---

### 2.5.6 入力メカニズムの共存 ✅ DS で担保

**達成基準**: 1 つの入力モダリティ（マウス / タッチ / キーボード）に縛られず、複数モダリティで操作可能。

**DS 側の担保**:
- すべてのコンポーネントが pointer / keyboard / touch すべてに対応
- マウスホバー専用 UI は無い

**プロダクト側の責務**:
- カスタムジェスチャー (ピンチ / 2 本指スワイプ等) を必須にしない
- タッチ専用の UX を作る場合、キーボードからの代替経路を提供

**チェック**:
- [ ] マウスを使わなくても全機能にアクセスできるか
- [ ] タッチを使わなくても全機能にアクセスできるか

---

## 4. Understandable (理解可能) — 7 基準

### 3.1.3 一般的でない用語 🔧 プロダクトの文章次第

**達成基準**: 一般的でない用語、業界用語、慣用句、隠語に対し、定義を提供する。

**プロダクト側の責務**:
- 専門用語に `<abbr>` / `<dfn>` でツールチップ
- ページ末尾に用語集を用意
- 初出時に「（用語：意味）」と注釈

**チェック**:
- [ ] 専門用語の定義が文中またはリンクで参照できるか

---

### 3.1.4 略語 🔧 プロダクトの文章次第

**達成基準**: 略語の意味を識別できる手段を提供する。

**プロダクト側の責務**:
- `<abbr title="Application Programming Interface">API</abbr>` のような明示
- 略語集ページの用意

**チェック**:
- [ ] 略語に `<abbr>` 等の展開情報があるか

---

### 3.1.5 読解レベル 🔧 プロダクトの文章次第

**達成基準**: 文章が前期中等教育（中学校レベル）を超える読解力を要求する場合、補足コンテンツ（要約 / 平易な言い換え）を提供する。

**プロダクト側の責務**:
- 専門記事には冒頭にやさしい言葉での要約を付ける
- 図解 / 動画での補完

**チェック**:
- [ ] 難しい記事に「ざっくり言うと」のような要約があるか

---

### 3.1.6 発音 🔧 プロダクトの文章次第

**達成基準**: 文脈から意味を取れない単語の発音情報を提供する（同音異義語 / 人名 / 専門固有名詞）。

**プロダクト側の責務**:
- ふりがな (`<ruby>`)
- IPA / カタカナ表記

**チェック**:
- [ ] 読み方が複数ある単語にルビが振られているか

---

### 3.2.5 要求による変化 ⚠️ DS + プロダクト共同

**達成基準**: コンテキストの変化はユーザーの明示的な操作後にのみ発生する（自動で起こさない）。

**DS 側の担保**:
- フォーム入力で勝手に submit / フォーカス移動が起きるパターンを提供していない
- タブ・アコーディオン等もユーザーのクリック / Enter が起点

**プロダクト側の責務**:
- フォーム要素の `onChange` で勝手にページ遷移しない
- スクロール位置をユーザー操作以外で動かさない
- 自動リダイレクト / 自動リフレッシュをデフォルトで使わない
- 必要な場合は事前にユーザーに知らせ、無効化可能にする

**チェック**:
- [ ] 入力欄を選んだだけでページが切り替わらないか
- [ ] フォームの input change で勝手に submit されないか
- [ ] 自動リダイレクトが無いか、ある場合は警告と無効化手段があるか

---

### 3.3.5 ヘルプ ⚠️ DS + プロダクト共同

**達成基準**: ユーザー入力を必要とするフォーム等に、文脈に応じたヘルプを提供する。

**DS 側の担保**:
- `.label-control-support` クラスで補足説明テキストを提供
- `.label-badge-required` / `.label-badge-optional` で必須・任意の明示
- `.alert` コンポーネントで入力エラー詳細を出せる

**プロダクト側の責務**:
- 各入力欄に **何を入力すべきか** の説明をラベル下に表示
- エラー時には **何が間違っていて** **どう直すか** を具体的に提示

**チェック**:
- [ ] 各入力欄に説明テキストが付いているか
- [ ] 必須項目が視覚的・プログラム的に明示されているか
- [ ] エラーメッセージが具体的か

---

### 3.3.6 誤り防止 (すべて) 🔧 プロダクトのフォーム実装

**達成基準**: ユーザーがデータ送信する操作に対して、以下のいずれかを提供:
1. 取り消し可能 (undo)
2. 送信前のエラーチェック + 修正機会
3. 送信前の確認ダイアログ

**プロダクト側の責務**:
- 重要な操作 (削除 / 退会 / 大金の決済) に確認ダイアログ
- フォーム送信前に内容確認画面
- 取り消し機能の提供（Snackbar の "Undo" ボタン等）

**チェック**:
- [ ] 削除 / 課金などの重大操作で確認画面があるか
- [ ] 送信前にエラーバリデーションが走るか
- [ ] 誤操作の取り消しができるか

---

## 5. Robust (堅牢) — AAA 基準なし

WCAG 2.1 では Robust 領域の AAA 基準は **存在しません**。

ただし A / AA レベルの基準（4.1.1 構文解析 / 4.1.2 名前・役割・値 / 4.1.3 ステータスメッセージ）は AAA を主張する前提として **必ず満たしてください**。

DS 側の関連:
- 4.1.2: 全コンポーネントが ARIA 属性で名前・役割・値を提供
- 4.1.3: `.alert` は `role="status"` / `role="alert"` を推奨

## 6. DS が既に提供する保証一覧（早見表）

| 担保 | 関連基準 | 利用方法 |
|---|---|---|
| 高コントラスト本文 | 1.4.6 | `text-fg-high` / `text-fg-middle` を使用 |
| キーボード操作 | 2.1.3 | `.btn` / `.input` 等の標準コンポーネントを使う |

| 入力共存 | 2.5.6 | キーボード / マウス / タッチすべて対応 |
| 見出し階層 | 2.4.10 | `.typo-*` を意味のある順序で使う |
| ヘルプ UI | 3.3.5 | `.label-control-support` / `.alert` |

## 7. プロダクト側で実装が必須なもの

DS で担保できない、プロダクト固有の責務:

| 領域 | 実装項目 |
|---|---|
| メディア | 動画の手話通訳・拡張音声解説・トランスクリプト (1.2.6-9) |
| 入力意味 | `autocomplete` 属性、ARIA ランドマーク (1.3.6) |
| 文字運用 | 文字画像を使わない (1.4.9) |
| タイムアウト | 20 秒以上前の警告、再認証時のデータ保持 (2.2.5, 2.2.6) |
| アニメ無効化 | `@media (prefers-reduced-motion: reduce)` グローバル CSS (2.3.3) |
| ナビ | パンくず・`aria-current="page"` (2.4.8) |
| リンク文言 | 「こちら」「more」を避ける (2.4.9) |
| ターゲット | 重要な操作には `lg` サイズを使う (2.5.5) |
| 用語・略語 | `<abbr>` / 用語集 / ルビ (3.1.3-6) |
| フォーム | 確認ダイアログ・undo 機能 (3.3.6) |

## 8. AAA 適用外と判断できるケース

サイトの性質によって、以下の基準は **対象外** として除外できます（その旨を準拠表記に明記）:

| 基準 | 適用外にできるサイト |
|---|---|
| 1.2.6 / 1.2.7 / 1.2.8 | 動画コンテンツを持たない |
| 1.2.9 | ライブ配信を持たない |
| 1.4.7 | 音声コンテンツを持たない |
| 2.2.5 / 2.2.6 | 認証セッションを持たない（公開情報のみ） |
| 3.1.6 | 発音が問題になる固有名詞・同音異義語が無い |

→ 詳細な準拠表記の書き方は [WAIC の準拠表記ガイドライン](https://waic.jp/docs/jis2016/compliance-guidelines/202104/) を参照。

## 9. 検証ツール

### 自動チェック（必須）

| ツール | 用途 |
|---|---|
| [axe DevTools](https://www.deque.com/axe/devtools/) | コントラスト / ARIA / HTML 構造の自動検査 |
| [Lighthouse (Chrome)](https://developer.chrome.com/docs/lighthouse) | Accessibility スコア + 詳細指摘 |
| [WAVE](https://wave.webaim.org/) | 視覚的なエラー / 警告マップ |
| [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) | 個別の色組み合わせ確認 |

### 手動チェック（必須）

自動検査では分からない項目（AAA で多い）:

- **キーボードのみで全操作**: Tab / Shift+Tab / Enter / Space / Esc / 矢印で各画面を一周
- **スクリーンリーダー**: NVDA (Win) / VoiceOver (Mac/iOS) / TalkBack (Android) で全フローを聞く
- **200% ズーム**: ブラウザを 200% にして横スクロール無しで使えるか
- **prefers-reduced-motion**: OS 設定でモーション削減を有効にしてアニメ確認
- **モバイル / タッチ**: 実機での操作性確認

### 監査の頻度

| タイミング | チェック内容 |
|---|---|
| PR レビュー時 | axe / Lighthouse 自動チェックでリグレッション検知 |
| 主要 release 前 | 手動チェック (キーボード + スクリーンリーダー + ズーム) |
| 四半期ごと | 全 28 基準のセルフチェック |
