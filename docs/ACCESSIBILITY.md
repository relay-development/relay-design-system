# relay Design System × WCAG 2.2 (A / AA / AAA) 実務チェックリスト

このドキュメントは **WCAG 2.2 の Level A / AA / AAA** に準拠したいプロダクトが、relay Design System を採用した時に「どこまで DS が担保していて、どこから自分たちで実装する必要があるか」を 1 枚で把握するためのチェックリストです。

> WCAG 2.2 (2023-10 勧告) は 2.1 に 9 基準を追加し、4.1.1 構文解析を廃止した最新の勧告です。本書では **2.2 で追加された基準を 🆕 で示します**。

> - [W3C - WCAG 2.2 (Recommendation)](https://www.w3.org/TR/WCAG22/)

## 0. このドキュメントの読み方

### 対象読者

- relay Design System を採用し、サイト全体で **A / AA / AAA いずれかのレベル** に準拠したいプロダクトチーム
- アクセシビリティ監査 / レビューで使うチェック項目を探している人

### 凡例

各達成基準には 2 種類のマーカーが付きます。

**Level マーカー**（WCAG が定める準拠レベル）

| マーカー | 意味 |
|---|---|
| `A` | 最低限。法的要件の最低ライン |
| `AA` | 標準。多くの自治体・企業の調達要件 |
| `AAA` | 最高。特に配慮した公共サービス向け |

**DS マーカー**（relay Design System の関与度）

| マーカー | 意味 | プロダクト側のアクション |
|---|---|---|
| ✅ | **DS で完全担保** | DS のクラス・トークンを使えば自動で満たす |
| ⚠️ | **DS + プロダクト共同** | DS が下地を提供。プロダクトが正しく使う |
| 🔧 | **プロダクト側で実装** | DS は関与しない。プロダクト固有の責務 |
| ⏩ | **コンテンツ次第で適用外** | 動画 / 音声 / セッション等が無ければ対象外 |

### 86 基準の内訳

| 領域 | A | AA | AAA | 計 |
|---|---|---|---|---|
| Perceivable (知覚可能) | 9 | 11 | 9 | 29 |
| Operable (操作可能) | 14 | 5 | 15 | 34 |
| Understandable (理解可能) | 6 | 6 | 9 | 21 |
| Robust (堅牢) | 1 | 1 | 0 | 2 |
| **合計** | **31** | **24** | **31** | **86** |

> 4.1.1 構文解析 (A) は WCAG 2.2 で廃止されたため Robust の A は 1 つ (4.1.2)。2.2 追加 9 基準: 2.4.11 / 2.4.12 / 2.4.13 / 2.5.7 / 2.5.8 / 3.2.6 / 3.3.7 / 3.3.8 / 3.3.9。

## 1. 準拠の前提

### Level の階層

```
Level A   (最低限)    →  Level AA  (標準・法規制ライン)  →  Level AAA (最高)
   ↑                        ↑                                ↑
   31 基準                   24 基準                          31 基準
   累積: 31                  累積: 55                         累積: 86
```

**上位レベルは下位を内包する**。AA を主張するには A をすべて満たした上で AA も満たす必要があり、AAA を主張するには A + AA + AAA すべてを満たす必要がある。

### relay Design System の全体的な担保サマリ

| 項目 | DS の実装状況 | 関連基準 |
|---|---|---|
| コントラスト本文 (AAA 7:1) | `fg-high` ≈18:1 / `fg-middle` ≈10.7:1 ✅ | 1.4.6 |
| コントラスト本文 (AA 4.5:1) | `fg-low` ≈4.5:1 ✅ | 1.4.3 |
| 非テキストコントラスト 3:1 | `stroke-middle` 等で確保 ⚠️ | 1.4.11 |
| キーボード操作 | 全 interactive 要素に `focus-visible` ✅ | 2.1.1 / 2.1.2 |
| Focus ring | `--shadow-focus-ring` + `outline-info-600` ✅ | 2.4.7 |
| ARIA 状態 | `aria-pressed` / `aria-selected` / `disabled` ✅ | 4.1.2 |
| 名前・役割・値 | ネイティブ HTML 要素ベース ✅ | 4.1.2 |
| ターゲット最小 44px | `.btn-lg` / `.icon-btn-lg` / `.input-lg` のみ ⚠️ | 2.5.5 |
| `prefers-reduced-motion` | **未対応** 🔧 | 2.3.3 |
| 見出し階層 | `.typo-*` で提供 ⚠️ | 2.4.6 / 2.4.10 |
| ステータスメッセージ | `.alert` + `role` 推奨 ⚠️ | 4.1.3 |

## 2. Perceivable (知覚可能) — 29 基準

### 1.1.1 非テキストコンテンツ `A` 🔧 プロダクト側

**達成基準**: 利用者に提示されるすべての非テキストコンテンツに、同等の目的を果たすテキスト代替を提供する。

**DS 側**: アイコンスプライト (`<svg class="icon">`) は `currentColor` で着色するだけのプリミティブ。代替テキストは提供しない設計。

**プロダクト側の責務**:
- 装飾アイコンには `aria-hidden="true"`、意味アイコンには `aria-label` または `<title>` を付ける
- 画像 (`<img>`) には用途に応じた `alt` 属性 (装飾は `alt=""`、内容ありは説明文)
- アイコンボタン (`.icon-btn`) には必ず `aria-label`

**チェック**:
- [ ] すべての `<img>` に `alt` 属性がある
- [ ] 装飾画像は `alt=""` または `aria-hidden="true"`
- [ ] アイコンのみのボタンに `aria-label` がある

---

### 1.2.1 音声のみ・映像のみ (収録済) `A` ⏩ コンテンツ次第

**達成基準**: 収録済み音声のみのコンテンツには代替テキスト、映像のみには代替テキストまたは音声を提供。

**プロダクト側の責務**:
- 音声のみ (ポッドキャスト等): トランスクリプトを提供
- 映像のみ (BGM 無しの説明動画等): 全文書き起こしテキスト or 音声トラック

**チェック**:
- [ ] 音声・映像メディアのトランスクリプトを用意しているか

---

### 1.2.2 キャプション (収録済) `A` ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディア (動画 + 音声) にキャプションを提供。

**プロダクト側の責務**:
- 動画には `<track kind="captions">` で字幕を付与
- YouTube 等の埋め込みなら自動字幕ではなく **手動キャプション** を準備

**チェック**:
- [ ] 全動画にキャプショントラックがある
- [ ] キャプションは話者識別・効果音を含む

---

### 1.2.3 音声解説またはメディアの代替 (収録済) `A` ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディアに音声解説または全文の代替テキストを提供。

**プロダクト側の責務**:
- 視覚情報が音声で補えない動画には、音声解説トラック or 全文書き起こし
- 全文書き起こしは映像内容も記述する

**チェック**:
- [ ] 動画の映像情報を音声か文章で補えているか

---

### 1.2.4 キャプション (ライブ) `AA` ⏩ コンテンツ次第

**達成基準**: ライブ同期メディアにキャプションを提供。

**プロダクト側の責務**:
- ライブ配信に **リアルタイム字幕** を提供 (人手の文字起こし or AI 字幕)

**チェック**:
- [ ] ライブ配信に同期キャプションがある

---

### 1.2.5 音声解説 (収録済) `AA` ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディアに音声解説を提供 (1.2.3 の上位要件)。

**プロダクト側の責務**:
- 視覚的に表示される重要情報を **音声トラック** で補う
- 通常の台詞の合間に挿入できる範囲で

**チェック**:
- [ ] 動画に音声解説トラックがあるか

---

### 1.2.6 手話 (収録済) `AAA` ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディアの音声に手話通訳を提供。

**プロダクト側の責務**:
- 動画にワイプの手話通訳を埋め込む (主に重要な公共コンテンツ)

**チェック**:
- [ ] 重要動画に手話通訳トラックがあるか

---

### 1.2.7 拡張音声解説 (収録済) `AAA` ⏩ コンテンツ次第

**達成基準**: 通常の音声解説 (1.2.5) で時間が足りない場合、動画を一時停止できる拡張音声解説を提供。

**プロダクト側の責務**:
- 必要に応じて動画再生を停止できる UI + 詳細な解説音声

**チェック**:
- [ ] 拡張音声解説が必要なコンテンツに対応しているか

---

### 1.2.8 メディアに対する代替 (収録済) `AAA` ⏩ コンテンツ次第

**達成基準**: 収録済み同期メディア・映像のみメディアの全文書き起こしを提供。

**プロダクト側の責務**:
- 動画ページに **全文トランスクリプト** ページへのリンクを置く
- トランスクリプトには視覚情報も含める

**チェック**:
- [ ] すべての収録メディアに全文書き起こしがあるか

---

### 1.2.9 音声のみ (ライブ) `AAA` ⏩ コンテンツ次第

**達成基準**: ライブ音声のみコンテンツに等価な代替 (リアルタイム文字起こし等) を提供。

**プロダクト側の責務**:
- ライブラジオ等にリアルタイムキャプションを提供

**チェック**:
- [ ] ライブ音声配信に同時キャプションがあるか

---

### 1.3.1 情報及び関係性 `A` ⚠️ DS + プロダクト共同

**達成基準**: 提示の情報・構造・関係性をプログラム的に決定可能にする (見た目だけで伝えない)。

**DS 側の担保**:
- セマンティック HTML 要素を活用 (`<table>` / `<th>` / `<fieldset>` 等)
- `.label-control` は `<label>` + ARIA で関連付け
- `.tabs` は `aria-selected` で active を明示

**プロダクト側の責務**:
- フォームに `<label for>` または `aria-labelledby` を必ず関連付け
- リストは `<ul>` / `<ol>` を使う (div で並べない)
- データテーブルに `<th scope>`
- 見出しは `<h1>`〜`<h6>` を使う (`.typo-*` をただの `<div>` に当てない)

**チェック**:
- [ ] スクリーンリーダーで構造が正しく読まれる
- [ ] 視覚的なグループ化 (色・余白) が必ず HTML 構造に対応している

---

### 1.3.2 意味のある順序 `A` ⚠️ DS + プロダクト共同

**達成基準**: コンテンツの提示順序がコンテンツの意味に影響する場合、正しい読み上げ順序をプログラム的に決定可能にする。

**DS 側の担保**:
- CSS `order` プロパティの濫用なし
- Flexbox / Grid を使っても DOM 順 = 読み上げ順を維持

**プロダクト側の責務**:
- `flex-direction: row-reverse` や `order` で DOM 順と視覚順を逆転させない
- どうしても必要な時は読み上げ順優先で DOM 構造を組む

**チェック**:
- [ ] CSS を無効化してもコンテンツが正しい順番で読める
- [ ] Tab 順序が視覚的順序と一致する

---

### 1.3.3 感覚的な特徴 `A` 🔧 プロダクト側

**達成基準**: 操作・理解の指示が、形状・色・サイズ・視覚的位置・方向・音だけに依存しない。

**プロダクト側の責務**:
- 「右側の青いボタンを押してください」ではなく「『保存』ボタンを押してください」
- 必須項目は色 (赤) だけでなく **マーク (`*`)** や **テキスト (必須)** で示す

**チェック**:
- [ ] 指示文が形状・色・位置だけで構成されていないか
- [ ] 色覚異常の人にも分かる代替手段があるか

---

### 1.3.4 表示の向き `AA` 🔧 プロダクト側

**達成基準**: コンテンツの表示・操作を単一の向き (縦・横のみ) に制限しない。

**プロダクト側の責務**:
- レスポンシブ CSS で縦横両対応
- iOS の縦固定 (`screen.orientation.lock`) を使わない

**チェック**:
- [ ] モバイルで縦横どちらでも表示できる

---

### 1.3.5 入力目的の特定 `AA` ⚠️ DS + プロダクト共同

**達成基準**: ユーザー情報を収集するフォームコントロールに、適切な `autocomplete` 属性を提供。

**DS 側の担保**:
- `.input` は標準 `<input>` をスタイルするだけ。`autocomplete` 属性をそのまま透過。

**プロダクト側の責務**:
- 氏名・メール・電話・住所・カード等の入力欄に [HTML autocomplete tokens](https://html.spec.whatwg.org/multipage/forms.html#autofill) を付与
- 例: `autocomplete="email"` / `"tel"` / `"street-address"` / `"cc-number"`

**チェック**:
- [ ] 個人情報入力欄に適切な `autocomplete` 属性がある

---

### 1.3.6 目的の特定 `AAA` ⚠️ DS + プロダクト共同

**達成基準**: UI コンポーネントの目的をプログラム的に判別可能にする (ARIA Landmark / role)。

**DS 側の担保**:
- ボタン / 入力 / セレクト等はセマンティック HTML
- 状態は ARIA 属性で表現

**プロダクト側の責務**:
- ページにランドマーク (`<header>` `<nav>` `<main>` `<footer>`) を配置
- カスタム widget には `role` 属性

**チェック**:
- [ ] スクリーンリーダーのランドマーク一覧で構造が把握できる

---

### 1.4.1 色の使用 `A` ⚠️ DS + プロダクト共同

**達成基準**: 色だけで情報・操作・反応・要素の区別を伝えない。

**DS 側の担保**:
- `.input-error` は色 + アイコン + テキストで通知
- `.alert-{success,negative,warning,info}` は色 + アイコン + 文言
- Filter Chip の active は色 + チェックアイコン

**プロダクト側の責務**:
- リンクは色だけで本文と区別せず、**下線** or アイコンで補強
- グラフは色だけでなくパターンやラベルで識別

**チェック**:
- [ ] グレースケール化しても意味が伝わる
- [ ] エラーが赤だけでなく文言・アイコンで示される

---

### 1.4.2 音声制御 `A` ⏩ コンテンツ次第

**達成基準**: 自動再生で 3 秒を超えて音声が出る場合、一時停止・停止または音量制御の手段を提供。

**プロダクト側の責務**:
- ページ読み込みで動画 / 音声を自動再生しない (default)
- やむを得ない場合は controls / mute toggle を表示

**チェック**:
- [ ] ページ表示時に勝手に音が鳴らない
- [ ] 鳴る場合は即座に止められる UI がある

---

### 1.4.3 コントラスト (最低限) `AA` ✅ DS で担保

**達成基準**: テキスト・文字画像のコントラスト比 **4.5:1 以上**。大きい文字 (18pt / 14pt+bold) は 3:1 以上。

**DS 側の担保**:
- `--color-fg-high` (slate-900) on white = 約 18:1 ✅
- `--color-fg-middle` (slate-700) on white = 約 10.7:1 ✅
- `--color-fg-low` (slate-500) on white = 約 4.5:1 ✅ (本基準ぴったり)

**ブランドカラーをテキストに使う時の注意**:
- コントラスト比は前景/背景を入れ替えても変わらない（緑文字 on 白 = 白文字 on 緑、同じ比率）
- `primary-500` (#30b686) は white と約 **2.57:1** → テキストには不適合
- 白背景の緑文字 / 緑背景の白文字は `primary-600` 以上 (AA)、`primary-800` で AAA
- `primary-500` は面・装飾 (ボタン塗り等) のみに使い、テキスト色には使わない

**プロダクト側の責務**:
- 本文に `text-fg-{high,middle,low}` を使う
- カスタム配色は必ずコントラストチェッカーで 4.5:1 を確認

**チェック**:
- [ ] 全テキストが 4.5:1 以上のコントラストを満たす
- [ ] `text-primary-500` を白背景の文字色に使っていない

**検証ツール**: axe DevTools / Chrome DevTools / WebAIM Contrast Checker

---

### 1.4.4 テキストのサイズ変更 `AA` ⚠️ DS + プロダクト共同

**達成基準**: テキストをスクロールや支援技術無しで **200% まで拡大可能**。

**DS 側の担保**:
- `.typo-*` は `rem` 単位 (`var(--text-*)`) ベース
- ユーザーのブラウザ font-size 設定に追従

**プロダクト側の責務**:
- `font-size` を `px` 固定値で上書きしない
- レイアウトを 200% ズームで破綻させない
- `viewport` メタタグで `user-scalable=no` を **設定しない**

**チェック**:
- [ ] ブラウザの 200% ズームで読みやすい
- [ ] レイアウトが崩れて操作不能にならない

---

### 1.4.5 文字画像 `AA` ✅ DS で担保 (DS では使わない)

**達成基準**: ロゴ等以外、文字情報は HTML テキストで提供する (装飾文字画像を避ける)。

**DS 側**: 文字画像は使用していない。テキストはすべて HTML。

**プロダクト側の責務**:
- 見出しを画像化しない
- 例外はロゴ・ブランドマークのみ

**チェック**:
- [ ] テキスト情報が画像化されていない

---

### 1.4.6 コントラスト (高度) `AAA` ✅ DS で担保

**達成基準**: テキスト・文字画像のコントラスト比 **7:1 以上** (大きい文字 4.5:1)。

**DS 側の担保**:
- `--color-fg-high` ≈ 18:1 ✅
- `--color-fg-middle` ≈ 10.7:1 ✅
- `--color-fg-low` ≈ 4.5:1 → **AA 止まり、AAA 本文には使わない** ⚠️

**プロダクト側の責務**:
- AAA 準拠時は本文に `text-fg-high` / `text-fg-middle` のみ使う
- カスタム配色は 7:1 を必ず確認
- ブランドカラーをテキストに使う場合の安全段階は [1.4.3](#143-コントラスト-最低限-aa--ds-で担保) 参照 (AAA は `primary-800`)

**チェック**:
- [ ] AAA 主張する画面で本文が 7:1 を満たす

---

### 1.4.7 小さな背景音、又は背景音なし `AAA` ⏩ コンテンツ次第

**達成基準**: 収録済み音声に背景音がある場合、前景音より 20dB 以上小さい (またはオフ可能)。

**プロダクト側の責務**: 音声コンテンツの BGM 音量管理

---

### 1.4.8 視覚的提示 `AAA` ⚠️ DS + プロダクト共同

**達成基準**: テキストブロックに対し、前景・背景色選択 / 段落幅 80 文字以下 (CJK 40) / 両端揃え禁止 / 行間 1.5 倍以上 / 段落間隔 1.5×行間 / 200% 拡大対応。

**DS 側の担保**:
- `.typo-*` の line-height は 1.5 前後 (例: 16px / 24px = 1.5)
- spacing トークンで段落間隔を確保しやすい

**プロダクト側の責務**:
- 本文最大幅を `max-width: 65ch` 等で制限
- `text-align: justify` を使わない
- テーマ切替で配色変更可能にする

**チェック**:
- [ ] 段落幅が読みやすい
- [ ] 両端揃えを使っていない
- [ ] 200% ズームで横スクロール無し

**達成基準** (WCAG 2.2 で追加): ドラッグ操作で行える機能には、**単一ポインタ (タップ / クリック) の代替** を提供する。

**DS 側**: DS はドラッグ依存のコンポーネントを持たない。

**プロダクト側の責務**:
- 並べ替え・スライダー等のドラッグ UI に、ボタンや選択での代替操作を用意

**チェック**:
- [ ] ドラッグでしかできない操作が無い

---

### 2.5.8 ターゲットのサイズ (最低限) `AA` 🆕 ✅ DS で担保

**達成基準** (WCAG 2.2 で追加): ポインタターゲットは **24 × 24 CSS px 以上** (または十分な間隔)。

**DS 側の担保**:
- 最小の `sm` サイズでも 32px (`.btn-sm` / `.icon-btn-sm` / `.input-sm`) → **24px を全サイズで満たす** ✅
- (AAA の 44px は [2.5.5](#255-ターゲットのサイズ-高度-aaa--ds--プロダクト共同) を参照)

**チェック**:
- [ ] すべてのターゲットが 24×24px 以上、または間隔で確保

---

## 4. Understandable (理解可能) — 21 基準

### 3.1.1 ページの言語 `A` 🔧 プロダクト側

**達成基準**: 各 Web ページの **主たる自然言語** をプログラム的に判別可能にする (`<html lang>` 属性)。

**プロダクト側の責務**:
- `<html lang="ja">` を必ず設定

**チェック**:
- [ ] `<html lang>` 属性が正しく設定されている

---

### 3.1.2 一部分の言語 `AA` 🔧 プロダクト側

**達成基準**: ページ内で異なる言語のコンテンツ部分に `lang` 属性を付与。

**プロダクト側の責務**:
- 英語の引用等に `<span lang="en">...</span>`

**チェック**:
- [ ] 多言語混在テキストに `lang` 属性がある

---

### 3.1.3 一般的でない用語 `AAA` 🔧 プロダクト側

**達成基準**: 業界用語・慣用句等の定義を提供。

**プロダクト側の責務**: `<abbr>` / `<dfn>` / 用語集ページ

---

### 3.1.4 略語 `AAA` 🔧 プロダクト側

**達成基準**: 略語の意味を識別できる手段。

**プロダクト側の責務**: `<abbr title="...">` / 略語集

---

### 3.1.5 読解レベル `AAA` 🔧 プロダクト側

**達成基準**: 中学レベルを超える文章には補足 (要約・図解等) を提供。

**プロダクト側の責務**: 専門記事に冒頭要約

---

### 3.1.6 発音 `AAA` 🔧 プロダクト側

**達成基準**: 文脈から発音が決まらない単語に発音情報を提供。

**プロダクト側の責務**: `<ruby>` ふりがな / IPA 表記

---

### 3.2.1 フォーカス時 `A` ✅ DS で担保

**達成基準**: コンポーネントがフォーカスを受けても、コンテキストの変化を **引き起こさない**。

**DS 側の担保**: フォーカス時に submit / ナビゲーション等を起こす設計はない

**プロダクト側の責務**:
- `onFocus` でページ遷移 / モーダル開く等をしない

**チェック**:
- [ ] Tab で要素にフォーカスしただけで画面が変わらない

---

### 3.2.2 入力時 `A` ✅ DS で担保

**達成基準**: UI コンポーネントの設定値変更で、コンテキストの自動変化を引き起こさない (利用者が事前に通知されている場合を除く)。

**DS 側の担保**: input change で勝手に submit / 遷移する実装は無い

**プロダクト側の責務**:
- セレクトの選択変更で勝手にページ遷移しない
- 必要な場合は事前に明示

**チェック**:
- [ ] フォームの選択 / 入力で勝手な遷移が起きない

---

### 3.2.3 一貫したナビゲーション `AA` 🔧 プロダクト側

**達成基準**: 複数ページで繰り返されるナビゲーションコンポーネントを **同じ相対順序** で配置。

**プロダクト側の責務**:
- グローバルナビの並び順をページ間で統一

**チェック**:
- [ ] ナビゲーションの順序がページ間で変わらない

---

### 3.2.4 一貫した識別性 `AA` ⚠️ DS + プロダクト共同

**達成基準**: 同じ機能を持つコンポーネントを、ページ間で **一貫したラベル・アイコン** で識別。

**DS 側の担保**: アイコン (Lucide) と命名規則で一貫性を担保

**プロダクト側の責務**:
- 同じアクションには同じラベル・同じアイコン
- 削除アイコンが場所によって `trash-2` と `x` で混ざらない

**チェック**:
- [ ] 同機能ボタンが画面間で同じ見た目

---

### 3.2.5 要求による変化 `AAA` ⚠️ DS + プロダクト共同

**達成基準**: コンテキスト変化はユーザーの明示的要求でのみ発生。

**DS 側の担保**: ユーザー操作起点のインタラクションのみ

**プロダクト側の責務**: 自動リダイレクト / リフレッシュを抑制

---

### 3.2.6 一貫したヘルプ `A` 🆕 🔧 プロダクト側

**達成基準** (WCAG 2.2 で追加): 複数ページで提供されるヘルプ機構 (問い合わせ先 / チャット / FAQ リンク等) を、**各ページで同じ相対順序** に配置する。

**プロダクト側の責務**:
- ヘッダー / フッターのヘルプ導線をページ間で同じ位置・順序に

**チェック**:
- [ ] ヘルプへの導線がページ間で一貫した位置にある

---

### 3.3.1 エラーの特定 `A` ⚠️ DS + プロダクト共同

**達成基準**: 入力エラーが自動的に検出された場合、エラー項目を特定し、**テキストで** ユーザーに伝える。

**DS 側の担保**:
- `.input-error` / `.textarea-error` で視覚的にエラー状態
- `.alert-negative` でエラーメッセージ表示

**プロダクト側の責務**:
- どの項目がエラーかをテキストで明示
- `aria-invalid="true"` / `aria-describedby` でエラーメッセージと関連付け

**チェック**:
- [ ] エラー項目がテキストで識別できる
- [ ] スクリーンリーダーでエラー内容が読まれる

---

### 3.3.2 ラベル又は説明文 `A` ⚠️ DS + プロダクト共同

**達成基準**: ユーザー入力を必要とするコンテンツに、ラベルまたは説明文を提供。

**DS 側の担保**:
- `.label-control` で `<label>` + サポートテキスト
- `.label-badge-required` / `.label-badge-optional`

**プロダクト側の責務**:
- 全入力欄に明示的なラベル
- placeholder だけのラベルは不可

**チェック**:
- [ ] 各入力欄に label がある
- [ ] 必須・任意が明示されている

---

### 3.3.3 エラー修正の提案 `AA` ⚠️ DS + プロダクト共同

**達成基準**: 入力エラーが検出され、修正方法が分かる場合、ユーザーに **修正候補** を提示する。

**DS 側の担保**: `.alert` の `alert-body` でメッセージ表示可能

**プロダクト側の責務**:
- 「メールアドレスの形式が違います。例: name@example.com」のように具体的に
- 候補があるなら「『〇〇』のことですか？」を提示

**チェック**:
- [ ] エラーメッセージが具体的で修正候補を含む

---

### 3.3.4 エラー回避 (法的・金融・データ) `AA` 🔧 プロダクト側

**達成基準**: 法的責任・金融取引・データ削除等を伴う操作には以下のいずれかを提供:
- 取り消し可能
- 送信前のエラーチェック + 修正機会
- 送信前の確認画面

**プロダクト側の責務**:
- 削除・購入・契約承認には確認ダイアログ
- 送信前確認画面

**チェック**:
- [ ] 重要操作に確認画面または undo がある

---

### 3.3.5 ヘルプ `AAA` ⚠️ DS + プロダクト共同

**達成基準**: ユーザー入力を必要とする箇所に、文脈に応じたヘルプを提供。

**DS 側の担保**: `.label-control-support` / `.alert` で補足表示

**プロダクト側の責務**: 各入力欄に説明 + エラー時の修正方法

---

### 3.3.6 誤り防止 (すべて) `AAA` 🔧 プロダクト側

**達成基準**: 3.3.4 の **全ての送信操作** に対するエラー回避手段。

**プロダクト側の責務**: 全ての送信に確認・undo・チェックのいずれか

---

### 3.3.7 冗長な入力 `A` 🆕 🔧 プロダクト側

**達成基準** (WCAG 2.2 で追加): 同一プロセス内で **既に入力した情報の再入力を求めない** (自動入力 / 既出値からの選択を可能にする)。

**プロダクト側の責務**:
- 配送先＝請求先のコピー、確認画面での再入力回避、autofill の活用

**チェック**:
- [ ] 同じ情報を 2 度入力させていない (再入力は自動入力 / 選択で代替)

---

### 3.3.8 アクセシブルな認証 (最低限) `AA` 🆕 🔧 プロダクト側

**達成基準** (WCAG 2.2 で追加): 認証で **認知機能テスト** (パズル / 文字の書き起こし / 記憶) を必須にしない。コピペ・パスワードマネージャ・パスキー等を許可。

**プロダクト側の責務**:
- パスワード欄の貼り付けを禁止しない、CAPTCHA に代替手段、WebAuthn / パスキー対応

**チェック**:
- [ ] 認証に認知パズルを必須にしていない
- [ ] パスワード貼り付け・自動入力を妨げない

---

### 3.3.9 アクセシブルな認証 (高度) `AAA` 🆕 🔧 プロダクト側

**達成基準** (WCAG 2.2 で追加): 3.3.8 の上位。オブジェクト認識・利用者固有情報も含め **認知機能テストを一切課さない**。

**プロダクト側の責務**: パスキー等、記憶・認知に依存しない認証手段を主とする

---

## 5. Robust (堅牢) — 2 基準

### ~~4.1.1 構文解析~~ `A` — WCAG 2.2 で廃止 (obsolete)

WCAG 2.2 で本基準は **削除** されました (現代のブラウザ・支援技術は多少のマークアップ不備を一貫して解釈できるため)。準拠判定の対象外ですが、HTML を valid に保つ運用 (重複 ID・未閉じタグの回避、W3C Markup Validation) は引き続き推奨されます。DS のコンポーネント HTML は valid 構造で提供しています。

---

### 4.1.2 名前 (name)・役割 (role)・値 (value) `A` ✅ DS で担保

**達成基準**: UI コンポーネントの**名前**と**役割**をプログラム的に判別可能、**状態**・**プロパティ**・**値**をプログラム的に設定可能で、変化が支援技術に通知される。

**DS 側の担保**:
- ネイティブ HTML 要素を使用 (`<button>` / `<input>` 等) → name / role が自動で確立
- 状態は `aria-pressed` / `aria-selected` / `disabled` で明示
- カスタム widget には `role` を付与

**プロダクト側の責務**:
- カスタム要素を作る場合は WAI-ARIA に従う
- 状態変化を `aria-*` 属性で支援技術に通知

**チェック**:
- [ ] スクリーンリーダーで全 UI コンポーネントの名前・役割・状態が読まれる

---

### 4.1.3 ステータスメッセージ `AA` ⚠️ DS + プロダクト共同

**達成基準**: ステータスメッセージ (成功・エラー・進捗等) を、フォーカス変更なしで支援技術に通知できるように、`role` または `aria-live` で識別する。

**DS 側の担保**:
- `.alert` コンポーネントは `role="status"` / `role="alert"` の付与を推奨 (ドキュメント済み)

**プロダクト側の責務**:
- フォーム送信成功時の Toast に `role="status"`
- エラーアラートに `role="alert"`
- 動的に追加されるメッセージに `aria-live="polite"` または `"assertive"`

**チェック**:
- [ ] スクリーンリーダーが Toast / アラートを自動的に読み上げる

## 9. 検証ツール

### 自動チェック（必須）

| ツール | 用途 |
|---|---|
| [axe DevTools](https://www.deque.com/axe/devtools/) | ARIA / コントラスト / HTML 構造 |
| [Lighthouse (Chrome)](https://developer.chrome.com/docs/lighthouse) | Accessibility スコア + 詳細指摘 |
| [WAVE](https://wave.webaim.org/) | 視覚的なエラー / 警告マップ |
| [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) | 個別の色組み合わせ確認 |
| [W3C Markup Validation](https://validator.w3.org/) | HTML 構文チェック (4.1.1 は 2.2 で廃止だが valid 維持を推奨) |

### 手動チェック（必須）

自動検査では分からない項目 (特に AAA で多い):

- **キーボードのみで全操作**: Tab / Shift+Tab / Enter / Space / Esc / 矢印キー
- **スクリーンリーダー**: NVDA (Win) / VoiceOver (Mac/iOS) / TalkBack (Android)
- **200% ズーム**: 横スクロール無しに読めるか (1.4.4)
- **320px 幅**: モバイル相当でリフロー可能か (1.4.10)
- **prefers-reduced-motion**: OS 設定でアニメ確認
- **`lang` 属性**: ブラウザ DevTools で確認

### 監査の頻度

| タイミング | チェック内容 |
|---|---|
| PR レビュー時 | axe / Lighthouse 自動チェック |
| 主要 release 前 | 手動チェック (キーボード + SR + ズーム) |
| 四半期ごと | 全 86 基準のセルフチェック |
